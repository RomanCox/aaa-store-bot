# Инструкции для coding-агентов

Проект — работающий Telegram-бот AAA Store для розничного и оптового каталога, импорта двух XLSX-прайсов, корзины и заказов. Стек: Node.js, TypeScript (strict, ES2020, CommonJS), node-telegram-bot-api (polling), SheetJS `xlsx`, Google Sheets API через `googleapis`, OpenRouter через `fetch`, Bottleneck и node-cron. Данные хранятся в JSON-файлах и памяти процесса.

## Ориентиры

- `src/index.ts` — bootstrap; `src/bot.ts` — подключение Telegram.
- `scripts/` — разовые скрипты для исправления ошибочно созданных записей в кеше товаров и других данных. После применения автоматический вызов можно убрать из точки запуска, сохранив скрипт для истории и ручного запуска. Миграции Duo и Glacier запускаются вручную. Реализация Duo находится в `src/migrations/`, порядок запуска — в [iphone-duo.md](docs/migrations/iphone-duo.md).
- `src/handlers/document.handler.ts`, `src/services/xlsx.service.ts` — импорт прайсов.
- `src/services/products/`, `src/services/catalog/`, `src/utils/priceFormat.ts` — идентификация товаров, предложения, каталог и цены.
- `src/handlers/callback.handler.ts`, `src/state/chat.state.ts`, `src/services/orders.service.ts` — корзина и отправка заказа.
- `src/services/helper.service.ts`, `src/texts/helper.texts.ts`, `src/keyboards/helper.keyboard.ts` — администраторский хелпер. Тексты логических блоков менять в `HELPER_CONTENT`, подписи ссылок — в `HELPER_LINK_LABELS`, URL — в `HELPER_LINKS`, названия разделов — в `HELPER_SECTION_LABELS`; `HELPER_TOPICS` собирает сообщения. Заголовки/пояснения хранить без HTML, разметку добавлять при сборке; цельные списки/примеры допустимо хранить в `*_HTML`. Меню редактируется, части памяток отправляются отдельно без удаления.
- `src/services/sheets.service.ts`, `src/services/warehouse.service.ts`, `src/services/xlsx.service.ts` — складские USD-предложения: по кнопке `loadWarehouseFromConfig` / `ingestWarehouseProducts` находят или создают карточки, при необходимости через существующий AI, и сохраняют кеш товаров, снимок склада и каталог. При старте `loadWarehouseFromFile` / `ingestWarehousePrices` только восстанавливают существующие позиции без AI и создания. Текущее поведение — [складские цены в архитектуре](docs/architecture.md#подтверждено-кодом-складские-цены).
- Подробности: [архитектура](docs/architecture.md). Задачи ведутся в Git issues; [docs/tasks/](docs/tasks/README.md) — только для дополнительного контекста при необходимости. Читать только документы, относящиеся к задаче.

## Соглашения и безопасность

- Сохранять существующий стиль соседнего кода: ES imports, функции сервисов, общие типы `src/types`, тексты `src/texts`, клавиатуры `src/keyboards`, рендер `src/render`. Форматирование смешанное; единого настроенного форматтера не найдено.
- Экспорты переменных, типов и утилитарных функций из папок организовывать через `index.ts` с реэкспортами. Если в папке есть такой `index.ts`, импортировать её публичные экспорты по пути папки: `import { getAssignableRoles } from "../../utils";`, а не из отдельного файла `../../utils/roles`. При добавлении нового файла в такую папку обязательно добавлять его публичные экспорты в существующий `index.ts` (например, `export * from "./roles";`). Перед завершением задачи проверять реэкспорты и использовать короткие импорты без расширения `.ts`.
- Все новые и изменяемые тексты, отправляемые пользователю бота (сообщения, подписи кнопок, ошибки, отчёты и отметки вместе с эмодзи), хранить в экспортируемых константах соответствующих файлов `src/texts/*.texts.ts`. Не встраивать тексты в обработчики, сервисы и рендер; для динамических сообщений использовать шаблоны/функции в `src/texts`. В тестах отображения использовать эти же константы, чтобы не дублировать формулировки и эмодзи.
- При переключении меню по кнопкам редактировать текст и inline-клавиатуру существующего активного сообщения через `renderScreen` / `editMessageText`, сохраняя его `message_id`; не делать обычный переход через удаление и повторную отправку. Владелец отметил мешающую анимацию частого удаления на iPhone. Новый экран при первом входе и отдельные сообщения инструкций/отчётов отправляются через `sendMessage`; это не повод удалять предыдущие части. Учитывать `activeMessageId` и `sections[section].messageId`: существующий рендер не всегда редактирует сообщение. Подробности и исключения — в [архитектуре](docs/architecture.md#переключение-экранов-и-сообщения).
- `CachedProduct` не содержит цен; цены принадлежат предложениям каталога. `PriceListType` использует точные строки источников; цены в типах — строки, валюта определяется источником и ролью.
- При добавлении складских `rawNames` сохранять канонический вариант: регион — флагом (`RU` → `🇷🇺`), SIM/активация — стандартными суффиксами. Исходное ненормализованное название не добавлять вторым алиасом; нормализация выполняется и при поиске. Существующие алиасы поставщиков сохранять.
- Для складского распознавания сначала отделять известные регион, SIM и активацию локально; в AI передавать только очищенное название товара. Метаданные добавляются к карточке после распознавания. Флаги региона и подтверждённый суффикс `RU` (`🇷🇺`) нормализуются в `warehouseNameParts`; остальные текстовые коды не угадывать.
- `manager_retail` наследует сценарии и цены `retail`, `manager_wholesale` — `wholesale`, без административных прав. Общие правила в `src/utils/roles.ts`. Складскую отметку видят обе менеджерские роли, `wholesale`, `admin`, `superadmin`; `retail` её не видит. Наличие склада не зависит от источника минимальной цены. Новые права менеджеров добавлять только по требованиям задачи.
- Наценки абсолютные; клиентские цены: опт — USD, розница — BYN. Курсы: `rub_to_usd` — RUB за 1 USD, `rub_to_byn` — BYN за 100 RUB, `usd_to_byn` — BYN за 1 USD. SIM, цвет и активация различают товары; для iPhone регион учитывается через SIM, отдельное различение регионов при одинаковом SIM сейчас не требуется. Определение цвета особенно важно для техники Apple. Склад хранится как источник `warehouse` в USD без количества и доставки +5 USD; резервирование/списание остатков и USDT не реализованы.
- После каждой реализованной функции и исправления ошибки актуализировать относящуюся к изменению документацию: фактическое поведение, ограничения и результаты проверок. Общее устройство отражать в `docs/architecture.md`, рабочие инструкции — в `AGENTS.md` и других соответствующих документах. Не описывать планы как готовые возможности и не дублировать список задач из Git issues.
- Не смешивать `getCatalogUIProducts` (фильтрация для интерфейса) с построением данных для отчётов/экспорта.
- Перед изменениями проверять `git status`; не откатывать чужие правки. Рабочие файлы могут отличаться от HEAD.
- Не читать `.env`, токены, credentials, приватные ключи, файлы авторизации (включая `google-service-account.json`); использовать имена переменных из исходников или безопасный пример окружения.
- Не запускать бота, watcher, dev-сервер, импорт, миграции, запись в рабочие JSON/CSV, Telegram-отправки и внешние запросы без явной авторизации задачи. Импорт может вызвать платный AI API и менять кеш ещё до обновления каталога.
- Не выполнять установку зависимостей, commit, push, deploy без соответствующего разрешения. Описание ручного деплоя не является разрешением его выполнять.
