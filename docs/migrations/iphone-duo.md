# Исправление кеша iPhone Duo

Скрипт запускается вручную и по умолчанию показывает план исправлений. Запуск с `--apply` исправляет сохранённый кеш. Это дополняет коррекцию представления в `getCatalogProducts`.

## Что меняется

`src/migrations/iphone-duo.migration.ts`, `planIphoneDuoMigration` и `migrateIphoneDuoCache`: у распознанных телефонов Apple iPhone Duo устанавливаются `category: "Смартфоны"` и `model: "iPhone Duo"`. Карточка, уже находящаяся в смартфонах, тоже исправляется, если модель записана как `Duo` или полное товарное название. Корректная карточка пропускается.

Используется существующая узкая проверка `getNamedIphoneDeviceModel` из `src/services/products/iphone.models.ts`. Air, другие товары, названия аксессуаров и неполные/нераспознанные названия не исправляются. ID, число карточек, `name`, `rawNames`, атрибуты, каталог предложений и история заказов не меняются. Объединения дублей нет.

## Запись и резервные копии

- Путь кеша — `PRODUCTS_CACHE_PATH` под `DATA_PATH`.
- При наличии исправлений до записи создаются точная резервная копия и JSON-отчёт в `../backups` относительно каталога кеша. При стандартном `./data` это `./backups`.
- Имена: `products-cache.before-iphone-duo.<timestamp>.<suffix>.json` и `migrate-iphone-duo.<timestamp>.<suffix>.json`.
- Отчёт содержит ID, название и прежние/новые `category` и `model`; это план исправлений. Успешную запись подтверждает сообщение о завершении в логах.
- Кеш записывается через `writeJsonFileAtomic`; перед заменой проверяется, что он не изменился с момента чтения.
- Если изменений нет, ничего не записывается и новые бэкапы не создаются. Отдельный маркер выполнения не нужен: повторный запуск идемпотентен.
- Отсутствующий кеш пропускается. Некорректный JSON, неверная структура, повторяющиеся ID, ошибка резервирования или записи завершают скрипт с кодом 1.

Для отката остановите бота и восстановите нужный кеш из резервной копии.

## Ручной просмотр и применение

Из корня проекта, без запуска бота:

```sh
node -r ts-node/register scripts/migrate-iphone-duo.ts
```

По умолчанию это только просмотр: список исправлений выводится в консоль, файлы не меняются. Для другого файла используется `--cache <путь>`. Без этого аргумента применяется `PRODUCTS_CACHE_PATH` из `DATA_PATH`. Скрипт не загружает `.env`; нужный `DATA_PATH` должен быть задан окружением процесса. Локальные цвета читаются из того же `DATA_PATH`.

Ручное применение допустимо только с остановленным ботом, чтобы его кеш в памяти не перезаписал исправленный файл:

```sh
node -r ts-node/register scripts/migrate-iphone-duo.ts --apply
```
