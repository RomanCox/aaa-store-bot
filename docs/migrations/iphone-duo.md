# Исправление кеша iPhone Duo

Реализовано автоматическое применение при старте бота и отдельный скрипт для предварительного просмотра. Это физическое исправление ранее сохранённого кеша; оно дополняет коррекцию представления в `getCatalogProducts`.

## Что меняется

`src/migrations/iphone-duo.migration.ts`, `planIphoneDuoMigration` и `migrateIphoneDuoCache`: у распознанных телефонов Apple iPhone Duo устанавливаются `category: "Смартфоны"` и `model: "iPhone Duo"`. Карточка, уже находящаяся в смартфонах, тоже исправляется, если модель записана как `Duo` или полное товарное название. Корректная карточка пропускается.

Используется существующая узкая проверка `getNamedIphoneDeviceModel` из `src/services/products/iphone.models.ts`. Air, другие товары, названия аксессуаров и неполные/нераспознанные названия не исправляются. ID, число карточек, `name`, `rawNames`, атрибуты, каталог предложений и история заказов не меняются. Объединения дублей нет.

## Автоматический запуск

В `src/index.ts` после загрузки локальных цветов вызывается `migrateIphoneDuoCache({ apply: true })`. Это происходит до `createBot`, polling и загрузки `productCache` в память. Затем бот загружает уже исправленный кеш обычным `loadProductCache`.

- Путь кеша — `PRODUCTS_CACHE_PATH` под `DATA_PATH`.
- При наличии исправлений до записи создаются точная резервная копия и JSON-отчёт в `../backups` относительно каталога кеша. При стандартном `./data` это `./backups`.
- Имена: `products-cache.before-iphone-duo.<timestamp>.<suffix>.json` и `migrate-iphone-duo.<timestamp>.<suffix>.json`.
- Отчёт содержит ID, название и прежние/новые `category` и `model`; это план исправлений. Успешную запись подтверждает сообщение о завершении в логах.
- Кеш записывается через `writeJsonFileAtomic`; перед заменой проверяется, что он не изменился с момента чтения.
- Если изменений нет, ничего не записывается и новые бэкапы не создаются. Отдельный маркер выполнения не нужен: повторный запуск идемпотентен.
- Отсутствующий кеш пропускается. Некорректный JSON, неверная структура, повторяющиеся ID, ошибка резервирования или записи прерывают запуск до Telegram; код завершения — 1. Сообщение `Bot started` выводится только после успешного bootstrap.

При откате сначала вернуть код без автоматического применения этой миграции и остановить процесс, затем восстановить нужный кеш из резервной копии: иначе при следующем старте исправление применится снова.

## Ручной просмотр и применение

Из корня проекта, без запуска бота:

```sh
node -r ts-node/register scripts/migrate-iphone-duo.ts
```

По умолчанию это только просмотр: список исправлений выводится в консоль, файлы не меняются. Для другого файла используется `--cache <путь>`. Без этого аргумента применяется `PRODUCTS_CACHE_PATH` из `DATA_PATH`. Скрипт не загружает `.env`; нужный `DATA_PATH` должен быть задан окружением процесса. Локальные цвета читаются из того же `DATA_PATH`.

Ручное применение допустимо только с остановленным ботом, чтобы его кеш в памяти не перезаписал исправленный файл:

```sh
node -r ts-node/register scripts/migrate-iphone-duo.ts --apply
```

При обычном обновлении приложения отдельный `--apply` не требуется: миграция включена в стартовый поток и компилируется в `dist` вместе с приложением. Сам скрипт из `scripts/` предназначен для ручного запуска через `ts-node`.

## Фактически выполненные проверки

- `node -r ts-node/register --test tests/iphone-duo-migration.test.ts tests/warehouse-prices.test.ts` — 89 тестов, все прошли: 11 миграционных и 78 регрессионных.
- Временные тестовые каталоги: исправление только двух полей, сохранение ID/атрибутов/алиасов, исключение аксессуаров и Air, предварительный просмотр, точная резервная копия, отчёт, применение, повторный запуск, отсутствие/повреждение кеша, дубли ID, сбой атомарной замены. CLI проверен отдельными процессами на временном `DATA_PATH`; сети и Telegram нет.
- `node node_modules/typescript/bin/tsc --noEmit` прошёл. CLI отдельно компилировался/выполнялся в тестах, поскольку `scripts/` не входит в основной `tsconfig.json`.
- Предварительный просмотр на локальном `data/products-cache.json` нашёл 13 исправлений: 12 карточек из аксессуаров и одну модель `Duo` у смартфона. SHA256 до и после совпал. Рабочий локальный кеш не записывался, `--apply` на нём не выполнялся.
- Реальный bootstrap бота, продакшен-миграция и деплой не запускались. Перед обновлением prod можно выполнить предварительный просмотр на сервере; применение произойдёт при последующем разрешённом запуске новой версии бота.
