# Хелпер в панели администратора

Статус: реализовано, локальные проверки пройдены; ожидается проверка владельцем в боте. Требования обновлены по последним уточнениям. После проверки владельцем документ можно перенести в архив; текущее поведение описано также в архитектуре.

## Назначение

Пошаговая памятка прямо в боте для администратора, который управляет пользователями, конфигом и складом. Хелпер только показывает инструкции, без изменения пользователей, настроек, товаров и цен, без Google/AI-запросов при открытии.

## Кнопки, доступ и навигация

1. Последняя отдельная строка действий `adminKeyboard` — `📚 Хелпер`, ниже остальных существующих действий.
2. Доступ только `admin` и `superadmin`. Проверять каждый callback, включая переходы из старых сообщений; менеджерам доступа нет.
3. Нажатие редактирует активный экран админ-панели: заголовок хелпера и три раздела, по кнопке в строке:
   - «Управление юзерами»;
   - «Заполнение конфига»;
   - «Заполнение склада»;
   - «Назад» — в основную админ-панель.
4. Выбор раздела отправляет отдельные сообщения последовательно: пользователи — ровно 3, конфиг — ровно 4, склад — 1. Части не перезаписываются друг другом.
5. Кнопки разделов и возврат размещаются под последней частью, без дополнительного сообщения ради клавиатуры. Старую клавиатуру можно убрать редактированием разметки, сохранив сам текст.
6. Последняя отправленная часть становится активным административным экраном: согласовать `activeMessageId` и `sections[SECTION.ADMIN_PANEL].messageId`. Возврат редактирует этот экран в основную панель; остальные сообщения остаются в чате.
7. Не удалять сообщения для обычного перехода меню и ради очистки истории: по наблюдению владельца, частое удаление вызывает заметную анимацию на iPhone. Если экрана ещё нет, допустима первая отправка.
8. Открытие/возврат устанавливают `mode: "idle"`, очищают ожидаемые ID добавления/редактирования, сохраняют корзину и остальные секции. Старый ввод ID, курса или прайса не должен продолжиться во время чтения.
9. Быстрые нажатия не должны перемешивать части памяток. При частичной ошибке отправки сохранить уже отправленные сообщения и восстановить кнопки для повтора.
10. Разделы должны дополняться через небольшой типизированный список, без отдельной системы управления контентом.

Опора — обычная ветка `renderScreen` / `editMessageText`, когда административный `messageId` совпадает с `activeMessageId`. Исключения существующего каталога не перерабатывать. Подробности — [архитектура](../architecture.md#переключение-экранов-и-сообщения).

## Содержание инструкций

Точные тексты и умеренные эмодзи хранятся в `src/texts/helper.texts.ts`: `HELPER_CONTENT` содержит логические блоки (заголовки, подзаголовки, пояснения, целые списки и примеры), `HELPER_LINK_LABELS` — подписи ссылок, `HELPER_SECTION_LABELS` — названия разделов. Заголовки и обычные пояснения не содержат HTML; теги заголовков/ссылок добавляются при сборке `HELPER_TOPICS`, обычный текст экранируется. Разметка остаётся внутри цельных блоков `*_HTML` со списками/примерами; каждый пункт в отдельную переменную не выносится. Документ задачи описывает требования к содержанию, а не вторую независимую копию строк.

### «Управление юзерами» — 3 сообщения

**1. Добавление и выбор роли**

- Начать с получения числового Telegram ID: не телефон и не `@username`.
- По уточнению владельца, показ ID есть только в десктопных версиях. **Windows/macOS: Настройки (Settings) → Общие (General) → Показывать ID чатов в профиле (Show Peer IDs in Profile)**. Включить настройку, открыть профиль нужного человека, скопировать ID. На Android/iPhone этой опции нет; использовать свой аккаунт на компьютере.
- «Админ-панель → Управление пользователями → Добавить пользователя», ввести ID только цифрами, выбрать роль, дождаться успеха; попросить человека отправить `/start` боту в личном чате.
- Роли: `retail` — розничный клиент, цены BYN без складской отметки; `wholesale` — оптовый клиент, USD и складская отметка; `manager_retail` / `manager_wholesale` — сотрудники с соответствующими клиентскими ценами и складской отметкой, без административных прав.
- `admin` — административные действия; `superadmin` — также назначение административных ролей. Админ назначает клиентские и менеджерские роли, а admin/superadmin назначает только суперадмин.
- Для цены клиенту использовать клиентский/менеджерский аккаунт: административная цена не включает клиентскую наценку. Самого себя добавить нельзя, существующий ID нужно редактировать.

**2. Удаление**

- Открыть профиль нужного человека в Telegram и скопировать его ID; напомнить про настройку показа ID на компьютере из первой памятки.
- В боте открыть управление пользователями, нажать «Удалить пользователя», отправить проверенный ID цифрами.
- Предупредить: удаление сразу после ввода, отдельного подтверждения сейчас нет.
- Дождаться сообщения об успешном удалении. Самого себя удалить нельзя; пользователь потеряет доступ. В список пользователей для получения ID заходить не нужно: он не помогает определить нужного человека.

**3. Редактирование**

- Получить ID нужного человека через его профиль в Telegram; в боте открыть управление пользователями и выбрать «Редактировать пользователя».
- Ввести ID цифрами, выбрать новую роль, дождаться сообщения об обновлении. В список пользователей для получения ID заходить не нужно.
- Меняется роль, не ID; напомнить ограничения назначения ролей и запрет редактирования себя. Отсутствующего пользователя сначала добавить.

### «Заполнение конфига» — 4 сообщения

**1. Ссылка и применение**

[Таблица конфига](https://docs.google.com/spreadsheets/d/1FMiacxRrb3wQTMBL2q3lgaVoNSOrMbepSXK2ujThvHk).

Листы «Ценообразование», «Брендообразование», «Цвета»; сохранять заголовки и порядок столбцов. После сохранения Google-таблицы нажать «Обновить конфиг» и прочитать отчёты. Эта кнопка обновляет также склад. Автоматического перечитывания Google при старте нет. Обновление брендов/цветов не означает массового переименования старых карточек; проверять импорт и каталог.

**2. Ценообразование**

Каждая строка — наценка для группы товаров и диапазона входной цены:
- A — точная категория; пусто — все категории указанного бренда.
- B — бренд; пусто — все бренды категории; оба пусты — общее правило. Для смартфонов не Apple код применяет бренд правил `Android`.
- C — максимум входной цены в USD включительно. В одной группе категории/бренда/ключевых слов границы проверяются по возрастанию, пустой максимум — последняя неограниченная ступень. Пример `500`, `1000`, пусто: до 500; свыше 500 до 1000; свыше 1000.
- D/E — отдельные суммы наценки в USD для опта/розницы, не проценты; бот учитывает валюту и округление.
- F — ключевое слово/словосочетание, например `iPhone 18`, для особой наценки. Несколько вариантов — каждый с новой строки внутри ячейки; достаточно одного совпадения, регистр не важен. Такие группы приоритетнее общих.
- Не создавать противоречащие конкурирующие группы: помимо приоритета ключевых слов важен порядок таблицы. Пустая/нулевая наценка пропускается при загрузке, не создаёт нулевую ступень. Без подходящей ненулевой наценки товар скрывается от клиентов.
- После обновления проверить оптовую/розничную цену.

**3. Брендообразование**

- A «Порядок» — число по возрастанию для порядка каталога, пустые/нечисловые — в конец.
- B «Бренды» — название бренда.
- C — слова/словосочетания, с которых начинается название товара в прайсе; несколько вариантов одного бренда в одной ячейке, каждый с новой строки.
- Пример Apple: `iPhone`, `MacBook`, `iPad`, если так начинается прайс. Начало должно совпадать целиком: `Mac` не означает любое слово на эти три буквы.
- Не повторять один префикс у разных брендов. Новая строка в редактируемой ячейке: Windows — Ctrl+Enter, macOS — ⌘+Enter. Сохранить, обновить конфиг, проверить импорт/порядок.

**4. Цвета**

- A «Цвет» — каноническое название для каталога.
- B «Ключевые слова» — варианты из прайса, каждый с новой строки в одной ячейке; напомнить сочетания клавиш.
- C «Модели» — ограничение по моделям, каждая с новой строки; пусто — общее правило. Ограниченное правило приоритетнее общего.
- Пример: Glacier / Blue / iPhone 18 превращает Blue этой линейки в Glacier, включая iPhone 18 Pro; остальные используют общее правило.
- Не создавать противоречащие правила одинаковой области действия. Цвет особенно важен для Apple: варианты могут иметь разные цены. Обновить конфиг и проверить распознавание при импорте.

### «Заполнение склада» — 1 сообщение

[Таблица склада](https://docs.google.com/spreadsheets/d/1iXWDip0zC7jScCI4Vjje7SnxHmdx5j3Em-sFqBeF_bo).

Памятка **только о названиях**, без объяснения колонок остатка/цены и выбора минимальной цены:
1. Копировать полное название из одного из прайсов поставщиков, без произвольных сокращений. Сохранять модель, поколение, память, RAM/SSD, цвет, размер и комплектацию.
2. Для iPhone обязательно SIM: `Esim`, `Dual Sim`, `Sim+Esim`; при активации — `(Active)`. Пример: `iPhone 17 Pro 256 Orange Esim`.
3. Для остальных товаров — регион, если он есть, флагом в конце: `MacBook Air 13 M5 24/512 Starlight 🇷🇺`. Для iPhone вместо региона указывать явный SIM.
4. Важная проверка: **название и параметры должны без догадок указывать ровно на один вариант товара**. Если подходят два и более, добавить недостающие отличия. `iPhone 17 Pro 256` недостаточно — нет цвета и SIM. Не объединять разные варианты под одним названием.
5. **Несколько одинаковых товаров разрешено вносить отдельными строками с одинаковым названием**, например для учёта серийного номера каждого экземпляра. Серийный номер записывать отдельно, не дописывать в название: он различает экземпляры, а не модель.
6. Сохранить, нажать «Обновить конфиг», проверить отчёт и карточку. При проблемах уточнить название и повторить.

Из справки исключена информация о ценах по просьбе владельца. Сам алгоритм складских предложений не меняется: существующий код учитывает их при выборе минимальной цены. Не добавлять в памятку неверное утверждение, что складская цена технически ни на что не влияет.

## Реализация и точки изменения

- `src/keyboards/admin.keyboard.ts` — последняя кнопка.
- `src/keyboards/helper.keyboard.ts` — клавиатура разделов, реэкспорт через `src/keyboards/index.ts`.
- `src/texts/helper.texts.ts` — все тексты, эмодзи, ссылки и типизированный список разделов; реэкспорт через `src/texts/index.ts`.
- `src/types/helper.ts` — `HelperTopic`; `src/types/actions.ts` — callbacks; `src/types/navigation.ts` — шаг `helper`; публичные типы — через `src/types/index.ts`.
- `src/services/helper.service.ts` — последовательная отправка, навигация, сброс ввода, очередь по чату и восстановление клавиатуры при ошибке.
- `src/handlers/callback.handler.ts` — маршруты и серверная проверка доступа.
- `src/handlers/back.handler.ts`, `src/render/renderSection.ts` — поддержка шага хелпера в существующей навигации.
- `src/render/renderScreen.ts` — использовать существующий механизм редактирования, без общего рефакторинга.

Хелпер не меняет правила пользователей, идентичности товаров, импорта и ценообразования. Не добавлять обязательные переменные окружения, сторонние ID-боты и внешние запросы при чтении справки.

## Проверки и критерии готовности

- Последняя кнопка админ-панели; корректные 3 раздела и возврат.
- Разрешённые admin/superadmin и запрет остальным ролям/неизвестному пользователю по каждому поддельному callback, включая возврат.
- Открытие редактирует прежний ID; части отправляются отдельно и по порядку (3/4/1), кнопки только у последней; возврат редактирует последнюю часть без удаления/дополнительного меню.
- ID активного сообщения согласован в состоянии; сброс ввода ID/курса/прайса, сохранение корзины.
- Первое открытие без сообщения, повторные нажатия, неизвестный раздел, частичный сбой и повтор, очередь нескольких запросов.
- Каждый текст укладывается в `TELEGRAM_MESSAGE_LIMIT`, HTML корректен; ссылки и тексты берутся из констант.
- Тесты с заглушкой Telegram, без удаления сообщений, Google/AI и записи рабочих данных. Реальные строки констант использовать в проверках количества/порядка.
- Проверка типов, тесты хелпера и нужные регрессии, `git diff --check`. Живая проверка Telegram — только при отдельной авторизации.
- Актуализировать архитектуру; архивировать задачу только после проверки владельцем. Будущие изменения действий бота отражать также в памятке.

## Уточнения и источники

Блокирующих вопросов нет. Путь показа Telegram ID и отсутствие мобильной опции подтверждены владельцем в текущем обсуждении; более ранние сведения о другом меню не используются в пользовательском тексте. Обе ссылки предоставлены владельцем, рабочие таблицы не открывались.

Сочетания новой строки Google Sheets подтверждены [официальной справкой Google](https://support.google.com/docs/answer/46973?co=GENIE.Platform%3DDesktop&hl=en). Проверка клиентских интерфейсов и реальная отправка в Telegram на этом этапе не выполнялись.

## Результат реализации и проверок

Уточнение после первой реализации: для удаления/редактирования ID получают через профиль человека в Telegram, а не из списка бота. Содержание разбито на `HELPER_CONTENT`, `HELPER_LINK_LABELS`, `HELPER_SECTION_LABELS`; заголовки и ссылки оформляются при сборке, цельные списки/примеры остаются с HTML в отдельных блоках. После этой правки прошли 21 тест хелпера, проверка типов и `git diff --check`; общий набор повторно не запускался. Новая проверка закрепляет путь получения ID из профиля. Живой бот и внешние сервисы не использовались.

Реализованы кнопка, три раздела и памятки, ссылки владельца, защищённые callback, редактирование меню, последовательные части, очередь по чату, сброс ожидаемого ввода, поддержка существующей навигации и восстановление кнопок при частичной ошибке. Все новые пользовательские строки находятся в текстах; новые файлы типов, текстов и клавиатур подключены к реэкспортам. Логика складских цен не менялась.

Выполнено:

- `node -r ts-node/register --test tests/admin-helper.test.ts tests/warehouse-prices.test.ts tests/ai-response.test.ts tests/iphone-duo-migration.test.ts` — 133 теста прошли, из них 20 — хелпер.
- `node node_modules/typescript/bin/tsc --noEmit` — без ошибок.
- `git diff --check` — без ошибок; Git сообщает предупреждения об окончаниях строк CRLF/LF в части файлов.

Тесты хелпера проверяют права на каждый callback, количество/порядок частей, кнопки и ID сообщения, отсутствие удаления, возврат и общий рендер, сохранение корзины, сброс ввода, неизвестный раздел, первый вход, очередь и отзыв доступа, частичную ошибку и повтор, длину текстов и HTML. Telegram/Google/сеть изолированы, рабочие JSON не записывались. Бот, импорт, сборка с записью в dist и деплой не запускались. На устройстве iPhone анимация не проверялась.
