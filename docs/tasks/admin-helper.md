# Хелпер в панели администратора

Статус: проект требований и текстов для согласования. Функция ещё не реализована. На этом этапе меняется только документация.

## Зачем нужна функция

Администратору нужна доступная прямо в боте пошаговая памятка: управление пользователями, заполнение конфига и склада. Инструкции должны объяснять действия обычным языком, показывать примеры и помогать проверить результат. Хелпер показывает справку; сам не изменяет пользователей, настройки, товары и цены.

## Кнопки, доступ и навигация

1. В `adminKeyboard` добавить последнюю отдельную строку с кнопкой `📚 Хелпер`. Она идёт ниже всех существующих действий панели; общая кнопка возврата, если добавляется рендером, остаётся навигацией ниже действий.
2. Доступ — только `admin` и `superadmin`. Проверять роль при каждом callback хелпера, включая переходы из старых сообщений. Менеджерам административный доступ не выдаётся.
3. Нажатие заменяет содержимое панели экраном `📚 Хелпер` с предложением выбрать раздел и кнопками, по одной в строке:
   - `Управление юзерами`;
   - `Заполнение конфига`;
   - `Заполнение склада`;
   - `Назад` — в основную панель администратора.
4. Выбор раздела отправляет отдельные сообщения последовательно, в указанном ниже порядке: управление — ровно 3, конфиг — ровно 4, склад — 1. Не заменять несколько инструкций одним редактируемым сообщением: все части должны оставаться доступными для чтения.
5. Под последним сообщением инструкции показать выбор трёх разделов и возврат в панель администратора, без дополнительного сообщения только ради кнопок. Навигация не запускает описанные в справке действия.
6. При открытии хелпера и возврате из него установить `mode: "idle"`, очистить ожидаемый ввод предыдущего административного сценария. Чтение справки не должно случайно продолжить ввод ID, курса или загрузку прайса. Корзину и прочие разделы не сбрасывать.
7. Разделы должны дополняться отдельными пунктами без переписывания общего механизма отправки. Достаточно небольшого типизированного списка разделов и массивов сообщений; отдельная система управления контентом не нужна.

## Черновики сообщений: «Управление юзерами»

### Сообщение 1 — добавление пользователя и выбор роли

**➕ Как добавить пользователя**

1. Сначала получите числовой Telegram ID человека. Это не номер телефона и не `@username`.
   - **Windows, Telegram Desktop:** откройте «Настройки → Продвинутые настройки → Экспериментальные настройки» и включите `Show Peer IDs in Profile`. Откройте профиль нужного человека и нажмите на ID, чтобы скопировать число.
   - **macOS, Telegram Desktop:** используйте тот же путь в Telegram Desktop. Отдельное приложение Telegram для macOS имеет другое меню; точный путь для него нужно сверить перед публикацией инструкции.
   - **Android:** точный путь в обычном официальном клиенте пока не подтверждён. Для получения ID откройте тот же аккаунт в Telegram Desktop на компьютере и скопируйте ID из профиля человека. Настройки Telegram X могут отличаться от обычного Telegram.
   - **iPhone:** точный путь включения показа ID пока не подтверждён. Используйте Telegram Desktop на компьютере с тем же аккаунтом, чтобы получить ID нужного человека.
2. В нашем боте откройте «Админ-панель → Управление пользователями → Добавить пользователя».
3. По запросу отправьте ID: только цифры, без `id:`, пробелов, запятых и других символов.
4. Выберите роль:
   - **Розничный клиент** (`retail`) — клиентские розничные цены в BYN, без складской отметки.
   - **Оптовый клиент** (`wholesale`) — оптовые цены в USD и отметка «На складе».
   - **Менеджер розницы** (`manager_retail`) — сотрудник с розничными ценами в BYN и складской отметкой.
   - **Менеджер опта** (`manager_wholesale`) — сотрудник с оптовыми ценами в USD и складской отметкой.
   - **Админ** (`admin`) — управление пользователями, прайсами и настройками; назначает только суперадминистратор.
   - **Суперадмин** (`superadmin`) — административный доступ с возможностью назначать также администраторов и суперадминистраторов; назначает только суперадминистратор.
5. Дождитесь сообщения «Пользователь успешно добавлен». После добавления попросите человека открыть личный чат с ботом и отправить `/start`.

Менеджерские роли не дают доступ к админ-панели. Для цены, которую нужно назвать клиенту, используйте соответствующий клиентский или менеджерский аккаунт: административная цена не включает клиентскую наценку. Самого себя добавить нельзя. Если ID уже есть в боте, используйте редактирование пользователя.

Редакторская оговорка: пункты о клиентах Telegram — черновик, а не готовая инструкция для публикации. Перед реализацией уточнить подтверждённые пути/названия меню на целевых версиях macOS, Android и iPhone либо согласовать указанный запасной способ через Desktop. Не выдавать неподтверждённый путь за существующую настройку. В готовом сообщении не должно остаться редакторских оговорок.

### Сообщение 2 — удаление пользователя

**➖ Как удалить пользователя**

1. Откройте «Админ-панель → Управление пользователями → Список пользователей».
2. Найдите нужного человека и скопируйте его числовой ID. Если сомневаетесь, сверьте ID с профилем человека в Telegram.
3. Вернитесь в управление пользователями и нажмите «Удалить пользователя».
4. Проверьте ID и отправьте его боту: только цифры.
5. Дождитесь сообщения «Пользователь успешно удалён» и проверьте список пользователей.

После отправки ID удаление выполняется сразу, без отдельной кнопки подтверждения. Пользователь лишится доступа к боту. Самого себя удалить нельзя. Если бот сообщает, что пользователь не найден, проверьте ID.

### Сообщение 3 — редактирование пользователя

**🔧 Как изменить роль пользователя**

1. Откройте «Админ-панель → Управление пользователями → Список пользователей».
2. Найдите нужного человека и скопируйте его числовой ID.
3. Вернитесь в управление пользователями и нажмите «Редактировать пользователя».
4. По запросу отправьте ID: только цифры.
5. Выберите новую роль по назначению из памятки о добавлении пользователя.
6. Дождитесь сообщения «Роль пользователя обновлена» и проверьте роль в списке.

Меняется роль, а не Telegram ID. Администратор может назначить клиентские и менеджерские роли; административные роли доступны для назначения только суперадминистратору. Самому себе изменить роль нельзя. Если пользователь ещё не добавлен, сначала добавьте его.

## Черновики сообщений: «Заполнение конфига»

### Сообщение 1 — ссылка и применение изменений

**🔗 Таблица конфига**

Откройте [таблицу конфига](https://docs.google.com/spreadsheets/d/1FMiacxRrb3wQTMBL2q3lgaVoNSOrMbepSXK2ujThvHk).

Нужные листы: «Ценообразование», «Брендообразование», «Цвета». Сохраните заголовки и расположение столбцов.

После правок дождитесь сохранения Google-таблицы, затем в боте нажмите «Админ-панель → Обновить конфиг» и прочитайте отчёты. Эта кнопка обновляет также склад. Правки таблицы сами по себе не загружаются в бот; при перезапуске бот берёт сохранённые локальные данные.

Изменения брендов и цветов не следует считать массовым переименованием уже сохранённых карточек: после обновления проверьте нужные товары в каталоге и отчёты импорта.

### Сообщение 2 — ценообразование

**💵 Как заполнить лист «Ценообразование»**

Каждая строка задаёт наценку для выбранных товаров и диапазона входной цены.

1. **Категория (A).** Укажите точное название категории из бота. Пусто — правило подходит ко всем категориям указанного бренда.
2. **Бренд (B).** Укажите точное название бренда. Пусто — правило подходит ко всем брендам указанной категории. Если оба поля пусты, правило получается общим для всех товаров: используйте его осознанно. Для смартфонов других брендов, кроме Apple, код выбирает правила по бренду `Android`.
3. **Максимальная цена (C).** Укажите верхнюю границу входной цены в USD, включительно. Пустая ячейка — диапазон без верхнего ограничения. Внутри одинаковой группы категории, бренда и ключевых слов сначала применяются заполненные границы по возрастанию, затем пустая: поэтому её используют для товаров дороже последней заполненной границы.
4. **Опт (D) и розница (E).** Укажите отдельные суммы наценки в USD, которые прибавляются ко входной цене. Это не проценты. Например, `20` означает прибавить 20 USD. Бот сам учитывает валюту источника, конвертацию и округление клиентской цены.
5. **Ключевые слова (F).** Необязательное ограничение по названию товара, например `iPhone 18`. Для нескольких вариантов используйте новую строку внутри той же ячейки. Достаточно совпадения одного варианта; регистр не важен. Такие правила приоритетнее общих, поэтому для новой модели можно задать отдельную повышенную или пониженную наценку.
6. После сохранения таблицы нажмите в боте «Обновить конфиг» и проверьте оптовую и розничную цены нужного товара.

Пример для одной категории, бренда и одинаковых ключевых слов: строки с максимумами `500`, `1000` и пустой ячейкой означают «до 500 включительно», «свыше 500 до 1000 включительно» и «свыше 1000».

Не создавайте несколько конкурирующих правил для одного товара без необходимости: кроме приоритета ключевых слов, код не выбирает автоматически «самое конкретное» правило — между подходящими группами важен порядок таблицы. Пустая или нулевая наценка не задаёт отдельную нулевую ступень: при загрузке она пропускается. Товар без подходящей ненулевой наценки скрывается из клиентского каталога.

### Сообщение 3 — брендообразование

**🏷 Как заполнить лист «Брендообразование»**

1. **Порядок (A).** Введите число, задающее место бренда в каталоге: меньшее число — выше в списке. Пустые и некорректные номера отправляют бренд в конец.
2. **Бренды (B).** Укажите название бренда так, как оно должно использоваться в боте.
3. **Ключевые слова (C).** Укажите слово или словосочетание, с которого начинается название товара этого бренда в прайсе. Для одного бренда можно указать несколько вариантов: каждый с новой строки в одной ячейке.
4. Например, для Apple можно перечислить начала названий `iPhone`, `MacBook`, `iPad`, если именно так они записаны в прайсах. Ключ должен совпадать с началом названия целиком; `Mac` не означает любое слово, начинающееся на эти три буквы.
5. Для новой строки внутри ячейки Google Sheets: **Windows — Ctrl+Enter, macOS — ⌘+Enter** во время редактирования ячейки. Обычный Enter завершает редактирование.
6. Не используйте одно и то же начало названия для разных брендов. Сохраните таблицу, нажмите «Обновить конфиг», проверьте порядок брендов и результат следующего импорта.

### Сообщение 4 — цвета

**🎨 Как заполнить лист «Цвета»**

1. **Цвет (A).** Укажите каноническое название цвета — как оно должно отображаться в каталоге.
2. **Ключевые слова (B).** Перечислите варианты названия цвета из прайсов. Каждый вариант — с новой строки в одной ячейке. Для новой строки: **Windows — Ctrl+Enter, macOS — ⌘+Enter**.
3. **Модели (C).** Если правило относится только к определённым моделям, перечислите их названия, каждое с новой строки. Пусто — общее правило цвета. Правила с моделями имеют приоритет над общими.
4. Пример: A — `Glacier`, B — `Blue`, C — `iPhone 18`. Тогда `Blue` в названии `iPhone 18` будет распознан как `Glacier`, а для остальных моделей продолжит действовать общее правило. Такое ограничение охватывает также варианты этой линейки, например `iPhone 18 Pro`.
5. Не добавляйте противоречащие друг другу правила одинаковой области действия. Сохраните таблицу, нажмите «Обновить конфиг» и проверьте распознавание цвета нужных товаров при импорте.

Цвет особенно важен для техники Apple: одинаковые модель и память с разными цветами могут иметь разные цены и должны оставаться разными товарами.

## Черновик сообщения: «Заполнение склада»

**📦 Как заполнить склад**

1. Откройте рабочую складскую таблицу, лист «склад». Название товара указывается в **A**, остаток — в **C**, входная цена в **USD** — в **D**. Бот получает только строки с остатком больше нуля; количество в каталоге не показывает. Цена должна быть числом больше нуля.
2. Возьмите полное название товара из одного из поставщицких прайсов. Не придумывайте сокращения. Сохраните точную модель, поколение, размер/память, RAM/SSD, цвет и остальные отличия комплектации, если они есть в названии прайса.
3. **Для iPhone обязательно укажите SIM:** например `Esim`, `Dual Sim` или `Sim+Esim`. Если товар активирован, добавьте `(Active)`. Пример: `iPhone 17 Pro 256 Orange Esim`. Разные SIM, цвета и активация — разные товары, даже если цена одинаковая.
4. **Для остальных товаров укажите регион, если он есть:** предпочтительно флагом в конце названия. Пример: `MacBook Air 13 M5 24/512 Starlight 🇷🇺`. Поддержан также суффикс `RU`: бот преобразует его в `🇷🇺`. Другие буквенные коды регионов автоматически не преобразуются. Для iPhone используйте явный SIM вместо региона.
5. **Перед сохранением проверьте однозначность:** представьте два похожих товара рядом. Можно ли по написанному названию и параметрам без догадок выбрать ровно один из них? Если подходят два или больше, название неполное — добавьте недостающие отличия. Например, `iPhone 17 Pro 256` недостаточно: не указаны цвет и SIM. Для MacBook нельзя терять RAM/SSD и известный регион; для комплектов — размер комплекта. Не объединяйте разные варианты под одним названием.
6. Дождитесь сохранения таблицы, нажмите в боте «Админ-панель → Обновить конфиг» и прочитайте отчёты. Склад не обновляется сам и не перечитывается из Google при запуске бота.
7. Проверьте товар в каталоге: модель, память, цвет, SIM/регион и складскую отметку. Если строка пропущена или не распознана, исправьте название/цену и обновите конфиг ещё раз. AI может помочь создать отсутствующий товар, но не гарантирует распознавание и не должен угадывать пропущенные отличия.

Главное правило: **одна складская строка должна однозначно описывать один вариант товара**. Совпадения только по модели недостаточно. Повторные строки одного варианта не суммируют количество: из их складских цен выбирается минимальная. Строка с нулевым остатком не попадает в складское предложение после обновления.

Редакторская оговорка: ссылка на складскую таблицу не предоставлена в этой задаче. Не подставлять ссылку на конфиг по предположению и не показывать фиктивную ссылку. При необходимости добавить ссылку отдельным требованием; текущая памятка начинает с уже известной администратору рабочей таблицы.

Отображаемая инструкция должна работать из локального кода. Редакторские замечания и техническую карту не отправлять пользователю.

## Проверки и критерии готовности

- Кнопка `📚 Хелпер` — последняя кнопка действия админ-панели; доступна admin/superadmin, недоступна остальным ролям, в том числе по поддельному callback.
- Меню заменяет панель; «Назад» возвращает обычные административные действия. Предыдущие режимы ввода не перехватывают сообщения во время чтения справки.
- Раздел пользователей отправляет 3 сообщения в порядке «добавление → удаление → редактирование», конфиг — 4 в порядке «ссылка → цены → бренды → цвета», склад — 1. Сообщения не перезаписывают друг друга, порядок не зависит от параллельных отправок.
- Каждый текст укладывается в `TELEGRAM_MESSAGE_LIMIT`; форматирование, URL, угловые скобки и специальные символы корректно обрабатываются выбранным `parse_mode`. Для HTML экранировать динамические значения. Не полагаться на автоматическую разбивку, которая изменит согласованное число сообщений.
- Тесты отправки используют реальные константы текстов и заглушку Telegram; проверяют количество, порядок и клавиатуру последней части. Не дублировать тексты целиком в тестах.
- Проверить возврат, повторное открытие и запрет доступа без изменений JSON, конфигурации, пользователей и каталога. Проверить отсутствие Google/AI-вызовов при чтении справки.
- Выполнить безопасную проверку TypeScript, тесты хелпера и затронутой навигации, существующие регрессии при необходимости, `git diff --check`. Живые проверки Telegram — только при отдельной авторизации. На этапе этого документа программные тесты функции не выполнялись: кода функции ещё нет.
- Перед публикацией справки сверить инструкции получения ID с фактическими версиями клиентов. Не смешивать Telegram Desktop, Telegram для macOS и Telegram X. Пока остаются неподтверждённые пути меню, не заявлять полное покрытие всех четырёх платформ.
- После реализации и проверки владельцем перенести описание фактического поведения в `docs/architecture.md`; документ задачи отправить в `docs/tasks/archive/`. Новые разделы и изменения существующих действий сопровождать актуализацией пользовательской памятки.

## Что ещё нужно уточнить перед публикацией текстов

Точные действия для получения ID в целевых версиях обычного Telegram на Android/iPhone и отдельного клиента macOS либо согласование запасного способа через Telegram Desktop. Это не мешает реализовать меню и остальные инструкции, но неподтверждённые настройки нельзя включать в готовую памятку как факт. Новые команды бота для получения ID и сторонние боты в эту задачу не включены.

Остальные решения для первого черновика приняты выше. Отдельная ссылка на склад необязательна для описанного сценария; её можно добавить после предоставления владельцем.
